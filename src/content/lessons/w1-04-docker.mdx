## 🛠 손으로 띄워 봐요

```bash
docker run --name dangdang-db \
  -e POSTGRES_PASSWORD=devpass \
  -e POSTGRES_DB=dangdang \
  -p 5432:5432 \
  -v dangdang-data:/var/lib/postgresql/data \
  -d postgres:16
```

| 옵션 | 뜻 |
|---|---|
| `--name` | 컨테이너 이름 |
| `-e` | 환경 변수 (비밀번호, 처음 만들 DB 이름) |
| `-p 내컴퓨터:컨테이너` | 포트 연결 |
| `-v 이름:경로` | 볼륨 연결 |
| `-d` | 뒤에서 실행 (터미널을 안 붙잡음) |

접속해서 테이블을 하나 만들어 봐요.

```bash
docker ps                                                # 실행 중인 컨테이너 보기
docker exec -it dangdang-db psql -U postgres -d dangdang  # 컨테이너 안 Postgres 접속
```

`psql` 안에서 `CREATE TABLE test (id serial, memo text);` → `\dt`로 확인 → `\q`로 나와요.

<Callout type="주의">`devpass` 같은 비밀번호는 **내 컴퓨터 연습용**이에요. 실제 서버 비밀번호는 코드에 적지 않고 GitHub Secrets 같은 곳에 둬요(7주차).</Callout>

## 볼륨이 진짜 남는지 확인

```bash
docker rm -f dangdang-db     # 분원 폐원 (컨테이너 삭제)
# 위의 docker run 명령을 다시 실행
docker exec -it dangdang-db psql -U postgres -d dangdang -c '\dt'
```

`test` 테이블이 그대로 있으면 볼륨 덕분이에요. `-v` 없이 해보면 사라져요.

## 여러 개를 한 번에 — docker-compose

당당은 Postgres(pgvector 포함)와 Redis가 같이 필요해요. 명령을 매번 치는 대신 파일 하나에 적어둬요.

```yaml
# compose.yaml
services:
  db:
    image: pgvector/pgvector:pg16
    environment:
      POSTGRES_PASSWORD: devpass
      POSTGRES_DB: dangdang
    ports: ["5432:5432"]
    volumes: [db-data:/var/lib/postgresql/data]
  redis:
    image: redis:7
    ports: ["6379:6379"]
volumes:
  db-data:
```

```bash
docker compose up -d     # 전부 켜기
docker compose ps        # 상태 보기
docker compose down      # 전부 끄기 (볼륨은 남아요)
```

<Callout type="요약">이미지 = 설계도, 컨테이너 = 분원, -p = 출입문, -v = 바깥 차트 창고, compose = 여러 분원을 한 장에 적은 개원 계획서.</Callout>

## 🛠 당당에 적용

1. `docker run`으로 Postgres를 띄우고 테이블을 하나 만들어요
2. 컨테이너를 지웠다가 다시 띄워서 테이블이 남는지 확인해요
3. 당당 레포에 `compose.yaml`을 **직접** 써서 db와 redis를 한 번에 띄워요
4. 에러가 나면 ＋ 새 페이지로 "에러 기록"을 만들어서 메시지와 해결법을 남겨요
