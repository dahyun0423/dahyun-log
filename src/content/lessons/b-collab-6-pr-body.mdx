## 🎬 장면

커밋 3개를 올리고 PR 화면을 열었는데 본문이 텅 비어 있다. "뭐라 쓰지…"
템플릿이 있었어도 마찬가지였을 거다. **칸이 있는 것과 칸에 뭘 쓸지 아는 것은 다르다.**

## 🗺 칸별로 무엇을 쓰나

| 칸 | 쓰는 법 | 어디서 가져오나 |
|---|---|---|
| 🚀 관련 이슈 | `closed #12`. 이슈가 없으면 "없음" | 이슈 번호 (브랜치 이름에 들어 있음) |
| 📝 작업 내용 | **결과 기준** 2~5줄. "w1-05.mdx 수정"이 아니라 "팀 Org 만드는 레슨 추가" | `git log --oneline develop..HEAD` |
| ✔️ 체크 리스트 | 실제로 확인했으면 `[x]`, **무엇으로 확인했는지 한마디** | `npm run build` 결과, base 확인 |
| 📸 스크린샷 | 화면이 바뀌었으면 전·후 | 로컬 dev 화면 |
| 💬 리뷰 요구사항 | 확신 없는 곳 하나만 콕 | 내가 제일 불안한 부분 |
| ➕ 추후 계획 | 이번에 일부러 안 한 것 | 머릿속 할 일 |

```bash
# 이 PR에 들어간 커밋만 보기 → 작업 내용의 재료
git log --oneline develop..HEAD
```

## 🛠 실제 예시 (docs/week1-team-setup PR)

```markdown
## 🚀 관련 이슈
- 없음 (이슈 없이 바로 작업 — 다음부터는 이슈 먼저)

## 📝 작업 내용
- 1주차 레슨 4편 추가: 팀 Organization(w1-05), 저장소 규칙(w1-06), 이슈·PR 템플릿과 README(w1-07), 공공데이터 API 키(w1-08)
- 협업 기초 카드 추가: 이슈로 시작하는 하루 + 새 저장소 체크리스트(b-collab-5)
- 로드맵 1주차에 팀 GitHub 세팅·공공데이터 키 추가

## ✔️ 체크 리스트
- [x] Merge 하려는 브랜치가 올바른가? — base: develop
- [x] 로컬에서 에러가 없는가? — npm run build 통과

## ➕ 추후 계획(선택)
- PR 템플릿 파일과 「PR 본문 뭐라 쓰나」 카드는 다음 PR로
```

PR 제목은 커밋 컨벤션 + 태그: `📝 [DOCS] 1주차 팀 GitHub 세팅·공공데이터 키 레슨`

## 🛠 템플릿은 언제 넣나

**저장소를 만들고 첫 커밋들 사이에.** 첫 PR보다 먼저.

1. `.github/PULL_REQUEST_TEMPLATE.md` 파일 만들기
2. `📝 Docs: PR 템플릿 추가`로 커밋
3. **기본 브랜치까지** 들어가야 새 PR에 자동으로 채워진다 (이 사이트는 main이 기본 → develop → main까지 머지)
