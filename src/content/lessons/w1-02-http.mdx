## 🎬 장면

지난 레슨에서 API를 **진료 의뢰서**라고 했다. 웹에서 이 의뢰서 양식의 이름이 **HTTP**다.
양식이 정해져 있어서, 어떤 창구(브라우저·앱)든 어떤 진료실(Spring·FastAPI)이든 서로 알아듣는다.

오른쪽 노트에서 Enter를 칠 때 이 사이트가 실제로 보내는 의뢰서:

```http
PUT /api/notes/w1-02-http HTTP/1.1      ← 메서드 + 경로
Host: dahyun-log.vercel.app             ← 헤더
Content-Type: application/json          ← 헤더: "본문은 JSON"
Cookie: dahyun_session=...              ← 헤더: 입원 팔찌 (로그인 증표)

{"title": "...", "blocks": [...]}        ← 본문
```

답장(응답)의 맨 윗줄 **상태 코드**가 "어떻게 됐는지"를 숫자로 알려준다.

```http
HTTP/1.1 200 OK
Content-Type: application/json

{"updatedAt": "2026-10-08T12:00:00.000Z"}
```

## 🗺 상태 코드 — 첫 자리만 봐도 반은 안다

| 코드 | 뜻 | 병원으로 | 이 사이트에서 실제로 |
|---|---|---|---|
| 200 | 성공 | 진료 완료 | 노트 읽기·저장 |
| 201 | 새로 만듦 | 새 차트 생성 | ＋ 새 페이지, 📁 새 폴더 |
| 400 | 요청이 이상함 | 의뢰서를 못 알아봄 | id에 대문자 |
| 401 | 누군지 모름 | 팔찌가 없음 | 로그인 안 함 |
| 403 | 권한 없음 | 이 진료과는 직원만 | (당당) 남의 기록 보기 |
| 404 | 없음 | 그런 차트 없음 | 아직 안 쓴 노트 |
| 500 | 서버 오류 | 진료실에 문제 | 서버 코드 버그 |
| 504 | 시간 초과 | 진료실이 기록실 답을 하염없이 기다림 | 배포 첫날의 DB 연결 멈춤 |

<Callout type="핵심">**4xx = 보낸 쪽(창구)이 고칠 것, 5xx = 받는 쪽(진료실)이 고칠 것.**</Callout>

## 🗺 주소 짓는 규칙 — REST

주소에는 **무엇(명사)**, 행동은 **메서드**로.

- 좋음: `PATCH /api/notes/abc` — "노트 abc를 일부 바꿔줘 (폴더 옮기기)"
- 나쁨: `POST /api/moveNote?id=abc` — 행동이 주소에 섞임

## 🛠 손으로 (터미널)

```bash
# 1) 로그인 없이 — 몇 번이 나올까?
curl -i https://dahyun-log.vercel.app/api/notes

# 2) 레슨 페이지는 누구나 — 몇 번?
curl -s -o /dev/null -w "%{http_code}\n" https://dahyun-log.vercel.app/learn/w1-02-http
```

`-i`는 답장의 상태 줄과 헤더까지 보여준다.
