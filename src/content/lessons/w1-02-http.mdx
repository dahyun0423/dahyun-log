## 주문서에도 양식이 있어요

지난 레슨에서 API를 **주문서**라고 했죠. 웹에서 이 주문서의 양식 이름이 **HTTP**예요.
양식이 정해져 있으니 어떤 홀(브라우저, 앱)이든 어떤 주방(Spring, FastAPI)이든 서로 알아들어요.

## 실제 주문서 한 장

오른쪽 노트에 글자를 칠 때마다 이 사이트가 실제로 보내는 요청이에요.

```http
PUT /api/notes/w1-02-http HTTP/1.1       ← 메서드 + 경로
Host: localhost:3123                      ← 헤더
Content-Type: application/json            ← 헤더: "본문은 JSON이에요"

{"title": "...", "blocks": [...]}         ← 본문
```

답장(응답)은 이렇게 생겼어요. 맨 위 **상태 코드**가 "어떻게 됐는지"를 숫자로 알려줘요.

```http
HTTP/1.1 200 OK
Content-Type: application/json

{"updatedAt": "2026-10-08T12:00:00.000Z"}
```

## 상태 코드 읽는 법

| 코드 | 뜻 | 식당으로 치면 | 이 사이트에서 |
|---|---|---|---|
| 200 | 성공 | 주문 완료 | 노트 읽기·저장 |
| 201 | 새로 만듦 | 신메뉴 등록 완료 | ＋ 새 페이지 |
| 400 | 요청이 이상함 | 주문서를 못 알아봄 | id에 대문자 |
| 401 | 누군지 모름 | "회원이세요?" | (당당) 로그인 안 함 |
| 403 | 권한 없음 | "직원만 들어갈 수 있어요" | 배포 사이트에서 저장 |
| 404 | 없음 | 없는 메뉴 | 아직 안 쓴 노트 |
| 500 | 서버 오류 | 주방에 불남 | 서버 코드 버그 |

<Callout type="핵심">**4xx는 보낸 쪽 잘못, 5xx는 주방 잘못.** 이것만 기억해도 디버깅 방향이 정해져요.</Callout>

## 주소 짓는 규칙 — REST

주소에는 **무엇(명사)**, 행동은 **메서드**로 나눠 적어요.

- 좋음: `PUT /api/notes/abc` — "노트 abc를 바꿔줘"
- 나쁨: `POST /api/saveNote?id=abc` — 행동이 주소에 섞임

당당 계획서의 `POST /visits/{id}/reports`도 같은 규칙이에요. "이 진료(visit)에 리포트를 새로 만들어줘".

## 직접 해보기 (터미널)

사이트가 켜진 상태에서 터미널에 쳐 보세요. `-i`는 답장의 상태 코드와 헤더까지 보여줘요.

```bash
# 1) 읽기 — 아직 안 썼으면 404, 썼으면 200
curl -i localhost:3123/api/notes/w1-02-http

# 2) 잘못된 주문서 — 몇 번이 나올까?
curl -i localhost:3123/api/notes/ABC

# 3) 터미널에서 노트 만들기 — 사이드바 '내 페이지'에 생겨요
curl -i -X PUT localhost:3123/api/notes/curl-test \
  -H "Content-Type: application/json" \
  -d '{"title":"curl로 만든 노트","lesson":null,"blocks":[],"markdown":"hello"}'
```

3번은 확인 후 `notes/curl-test.*` 파일을 지워요.

<KeySentence note="상태 코드 첫 자리만 봐도 누구 문제인지 보여요.">4로 시작하면 내가 잘못 보냈고, 5로 시작하면 서버가 잘못했다</KeySentence>
