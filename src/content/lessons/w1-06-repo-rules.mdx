## 🎬 장면

규칙은 노션에 다 적어 놨다. `main` 직접 push 금지, PR은 develop으로, Squash로 합치기.
그런데 새벽 2시에 급하게 고치다 보면 `git push origin main`을 쳐 버린다. **사람은 까먹는다. 설정은 안 까먹는다.**

## 🛠 1. 머지 버튼·브랜치 자동 삭제

저장소 **Settings → General** → 아래로 내려 **Pull Requests**

- ☐ Allow merge commits — **끈다**
- ☑ Allow squash merging — feature → develop
- ☑ Allow rebase merging — develop → main
- ☑ **Automatically delete head branches** — 머지하면 feature 브랜치가 알아서 지워진다 (골드상 팀도 이렇게 했다)

## 🛠 2. 기본 브랜치를 develop으로

1. develop 브랜치를 먼저 만들어 push (위 FlowSim)
2. **Settings → General → Default branch** 옆 ⇄ 버튼 → `develop` 선택 → *Update*

```bash
# 내 컴퓨터도 맞춰 두기
git fetch origin
git switch develop
```

## 🛠 3. 브랜치 보호 — Rulesets

**main·develop에 직접 push 못 하게 막는 단계.** 저장소마다 규칙 **1개**로 main·develop을 같이 묶는다.

1. **Settings** → 왼쪽 *Code and automation* → **Rules → Rulesets**
2. **New ruleset → New branch ruleset**
3. **Ruleset Name**: `protect-main-develop`
4. **Enforcement status**: `Disabled` → **Active** ⚠️ 안 바꾸면 규칙이 안 걸린다
5. **Bypass list**: 비워 둔다 (여기 넣은 사람은 규칙을 무시할 수 있다)
6. **Target branches → Add target → Include by pattern** → `main` → *Add inclusion pattern*, 한 번 더 → `develop`
7. **Branch rules** 체크

| 칸 | 넣을 것 |
|---|---|
| ☑ Restrict deletions | main·develop 삭제 금지 (기본 켜짐) |
| ☑ Require a pull request before merging | 펼쳐지면 Required approvals `0` → **1** |
| ☑ Block force pushes | `push -f` 금지 (기본 켜짐) |
| ☐ Require status checks to pass | **CI를 만든 뒤에** 켠다. 지금 켜면 고를 체크가 없어서 아무것도 머지가 안 된다 |

8. 맨 아래 **Create** → `dangdang-be`, `dangdang-ai`도 똑같이

**걸고 나면 달라지는 것**
- main·develop에는 **PR로만** 넣을 수 있다. 웹에서 바로 커밋하는 것도 막힌다
- PR은 **상대가 Approve해야** 머지된다 (내 PR은 승민 언니가, 언니 PR은 내가)
- 저장한 뒤 시험: `git push origin main` → **거절되면 성공**
- 정말 급할 때만 Owner가 Enforcement를 잠깐 Disabled로 바꾼다

<Callout type="핵심">당당은 10/10에 **일단 보류**했다. 초기 세팅 커밋(Start·의존성·설정)을 develop에 편하게 올린 뒤, 본격적으로 기능 PR을 주고받기 시작할 때 건다. 무료 Org라 저장소가 **Public**이어야 강제된다.</Callout>

<Callout type="주의">CI(GitHub Actions)를 만든 다음 **Require status checks**에 체크 이름(예: `Code Style Check`, `Build`)을 추가해야 "CI 통과해야 머지"가 진짜로 걸린다. CI는 한 번 돌아야 목록에 나온다.</Callout>

<Callout type="핵심">**저장소를 만들기 전에** Org **Settings → Repository → Repository defaults → Repository labels**에 8개를 넣어 두면, 그 뒤 만드는 저장소에 **자동으로** 들어간다. 기본 라벨 9개(`bug`, `enhancement`…)는 겹치거나 안 쓰니 지운다. 당당은 이렇게 해서 저장소 3개에 라벨이 한 번에 생겼다.</Callout>

이미 만든 저장소에 넣을 때는 터미널로 (gh 로그인 후):

```bash
gh label create feat -R dangdang-2026/dangdang-be --color eed745
```

## 🛠 5. 마일스톤 — 주차별

**Issues → Milestones → New milestone**

- Title: `1주차 기획 확정·환경 구성`, Due date: `2026-10-14`
- 9주차까지 계획서 일정 그대로 만든다
- 이슈를 만들 때 오른쪽 **Milestone**에서 주차를 고르면, 마일스톤 화면에 **진척률 %**가 뜬다

## 🛠 6. Projects 보드 — 저장소 3개를 한 판에

1. **Org 페이지 → Projects → New project → Board**
2. 열 이름: `Todo` → `In Progress` → `Review` → `Done`
3. 보드 오른쪽 위 **⋯ → Workflows → Auto-add to project**: 저장소마다 켜면 새 이슈가 자동으로 보드에 들어온다
4. 저장소 **Projects 탭 → Link a project**로 연결

<Callout type="요약">머지 버튼(Squash·Rebase만) → 브랜치 자동 삭제 → develop 기본 → Rulesets(main·develop, PR+승인1, force push 금지) → 라벨 8개 → 마일스톤 9개 → Projects 보드</Callout>
