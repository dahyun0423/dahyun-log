## 🗺 이메일 가입·인증·로그인 (AUTH-02~04)

| 단계 | 서버가 하는 일 |
|---|---|
| 가입 | 이메일 중복 확인, 비밀번호 규칙(8자 이상·영문·숫자), **BCrypt 해시**로 저장 |
| 인증번호 | 6자리를 만들어 **Redis에 제한시간과 함께** 저장 → 메일 발송. 5회 틀리면 다시 받기, 재발송 하루 5번 |
| 로그인 | 해시 비교. 5회 실패하면 잠시 잠금(남은 횟수 표시) |
| 비밀번호 찾기 | 가입 여부와 **상관없이 같은 안내**. 링크 30분·1회용 |

| 비밀번호 바꾸기 M-09 | `PATCH /me/password` | **현재 비밀번호 확인** 먼저, 이메일 가입자만 |
| 로그아웃 M-10 | `POST /auth/logout` | Redis의 Refresh 삭제 |
| 탈퇴 M-07·08 | `DELETE /me` | 개인 데이터 즉시 삭제 (가능하면 이번 주) |

## 🛠 구현 순서 (추천)

1. `users` · `consents` 테이블 → Flyway `V1__init.sql` (ERD 확정본)
2. `POST /auth/signup` + BCrypt → 테스트 먼저(비밀번호 규칙, 중복 이메일)
3. `POST /auth/login` → `JwtProvider`(Access·Refresh) → httpOnly 쿠키
4. `JwtAuthenticationFilter` + `SecurityConfig` → `GET /me` 200 확인
5. `POST /auth/refresh` · `POST /auth/logout` (Redis)
6. 이메일 인증번호 (Redis 제한시간)
7. 카카오 `POST /auth/kakao`
8. 마이 API → Swagger 캡처 → 멘토링

<Callout type="주의">Boot 4 + jjwt·springdoc 버전 호환을 먼저 확인한다(ADR-0001). 블로그의 Boot 3 예제를 그대로 복사하면 패키지 이름이 달라 안 돈다.</Callout>

<Callout type="요약">인증=신분증, 인가=출입 권한. 비밀번호는 BCrypt 해시. Access(짧게)+Refresh(Redis) httpOnly 쿠키. 카카오 코드 교환은 서버. 순서: V1 → 가입 → 로그인·JWT → 필터·/me → refresh·logout → 인증번호 → 카카오 → 마이.</Callout>
