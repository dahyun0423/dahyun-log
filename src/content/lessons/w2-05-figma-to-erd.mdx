## 🛠 화면 → ERD 5단계

**1. 화면에서 '저장되는 것'에 동그라미**
입력칸, 칩, 토글, 목록, 카드. 새로고침해도 남아야 하는 건 전부 저장 대상이다.

**2. 명사 = 테이블 후보**
"식사를 시작한다" → `meals`, "혈당을 적는다" → `readings`, "알림이 온다" → `reminders`

**3. 입력칸 = 컬럼**
각 칸마다 *타입*(숫자·글자·시각)과 *비워도 되나*를 적는다.

**4. '하나에 여러 개' = 관계(1:N)**
"여러" 쪽 테이블에 FK를 넣는다.

**5. 계산할 수 있는 건 저장하지 않는다**
저장하면 원본과 계산값이 어긋날 때 무엇이 맞는지 모른다.

## 🛠 연습: 혈당 입력 시트(G) → readings

| 화면에 보이는 것 | 컬럼 | 타입 | 비워도? |
|---|---|---|---|
| 누구의 기록 | `user_id` | FK → users | ✗ |
| 공복 / 식후 / 기타 | `kind` | 글자(정해진 값) | ✗ |
| 어느 끼니 뒤 | `meal_id` | FK → meals | ✓ (공복이면 없음) |
| 알림이 정한 시각 | `scheduled_at` | timestamptz | ✓ |
| 실제로 잰 시각 | `measured_at` | timestamptz | ✗ |
| 숫자 키패드 값 (20~600) | `value` | 정수 | ✗ |
| 그때 적용된 기준 | `criteria_version_id` | FK | ✓ (모르면 비교 안 함) |
| 삭제 (복구 가능) | `deleted_at` | timestamptz | ✓ |

## 🗺 당당 테이블과 관계 (기능명세서 11절 초안)

```text
users 1 ─┬─ N meals 1 ── N meal_items
         ├─ N readings ── (선택) meals
         ├─ N criteria_versions ←── readings.criteria_version_id
         ├─ N reminders
         ├─ N push_subscriptions
         ├─ N consents
         ├─ 1 pregnancy
         ├─ N insulin_logs · visits · audit_logs
         └─ N ask_threads · posts (챗봇·커뮤니티, 10/15 추가)
ai.foods  ← meal_items.food_code (식약처 DB, 벡터 검색)
```

<Callout type="핵심">당당이 **저장하지 않고 계산하는 값**: ① '목표 밖' 여부(그 기록의 기준 버전으로) ② 늦게 잼(`measured_at - scheduled_at`) ③ 임신 주수(출산예정일 기준). 기준이 바뀌어도 **지난 기록은 그때 기준**으로 보인다.</Callout>
