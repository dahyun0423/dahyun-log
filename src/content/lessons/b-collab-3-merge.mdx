## 🎬 장면

PR을 합칠 때 GitHub는 세 가지 버튼을 준다. 결과 파일은 같아도 **기록이 남는 모양**이 다르다.

## 🗺 세 가지 버튼

| 방식 | 하는 일 | 원래 커밋 | 비유 |
|---|---|---|---|
| **Create a merge commit** | "합쳤음" 기록을 하나 더 남김 | **그대로 연결** | 두 차트를 끈으로 묶음 |
| **Squash and merge** | 여러 커밋을 **새 커밋 하나로** 뭉침 | 버려짐 (복사본) | 경과 기록 10줄을 요약 1줄로 |
| **Rebase and merge** | 커밋을 **하나씩 복사해서** 끝에 붙임 | 버려짐 (복사본) | 차트를 베껴 써서 이어 붙임 |

## 🗺 이 레포의 규칙

| 방향 | 방식 | 이유 |
|---|---|---|
| `feature/*` → `develop` | **Squash** | 작업 중 커밋 여러 개를 기능 하나로 깔끔하게 |
| `develop` → `main` | **Create a merge commit** | 원본을 그대로 연결 → 쌍둥이 안 생김 |

당당 팀 규칙(develop→main Rebase)은 그대로 두되, 같은 충돌이 나면 이 카드를 다시 본다.

## 🛠 Squash 후 브랜치 지우기

Squash는 원래 커밋을 버리고 새 커밋을 만들기 때문에, 로컬에서 `git branch -d`가 "아직 안 합쳐졌는데?"라고 경고한다. merge된 걸 확인했으면 `-D`로 지운다.

```bash
git switch develop && git pull
git branch -D feature/끝난-작업
```
