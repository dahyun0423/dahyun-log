## 🗺 카카오 키 5종 — 어디에 두나

| 키 | 하는 일 | 공개돼도? | 어디에 |
|---|---|---|---|
| **REST API 키** (`client_id`) | 우리 앱이 누구인지 카카오에 알림 | △ 로그인 주소에 들어가서 사실상 보임 | 프론트(로그인 주소) + 서버 |
| **클라이언트 시크릿** | 토큰 교환 때 "진짜 우리 서버"임을 증명 | ❌ | **서버 `.env`만** |
| **JavaScript 키** | 브라우저에서 카카오 SDK·지도 | ⭕ 대신 **등록 도메인에서만** 동작 | 프론트 |
| 네이티브 앱 키 | 안드로이드·iOS 앱 SDK | — | 안 씀 |
| 어드민 키 | 모든 권한(위험) | ❌❌ | **아무 데도 안 넣음** |

**공개될 걸 전제로 만든 키는 다른 조건(도메인·등록 주소)으로 지키고, 공개되면 끝인 키는 서버에만 둔다.** 이게 키를 나누는 기준이다.

## 🛠 비밀값은 레포마다 .env 하나

```text
dangdang-be/.env        ← Spring: DB, 카카오 REST·시크릿·리다이렉트
dangdang-ai/.env        ← FastAPI: 공공데이터 키(계정당 1개), AI 키, 내부 토큰
GitHub Secrets ENV_PROD ← 서버용 .env 전체
```

- `.env`는 `.gitignore`로 **커밋 안 됨**(확인: `git check-ignore .env`), 레포에는 값 없는 **`.env.example`**만
- 처음엔 레포 밖 폴더에 키 파일을 따로 만들었는데 흩어져서 헷갈림 → 선배들처럼 레포별 `.env`로 합침
- 언니(프론트)에게는 REST API 키·리다이렉트 URI·JavaScript 키만. **클라이언트 시크릿은 주지 않는다**
- Spring은 `.env`를 자동으로 안 읽는다 → 코드 짤 때 `spring.config.import=optional:file:.env[.properties]` 등으로 연결

## 🛠 공공데이터 키 — 승인됐는데 안 될 때

1. 키 지문이 포털과 같은지 확인(값을 화면에 띄우지 않고 비교) → 같았다
2. 주소가 맞는지 → `…FoodNtrCpntDbInfo02/getFoodNtrCpntDbInq02` (01은 '폐기됨' 코드 12)
3. 남은 원인 = **반영 대기**(코드 30). 1~2시간 뒤 다시

<Callout type="요약">로그인은 인가 코드(1회용) → 서버가 시크릿으로 토큰 교환. 시크릿·어드민 키는 서버에만, JS 키는 도메인 제한, 리다이렉트 URI는 등록한 곳만. 동의항목은 최소로. 비밀값은 레포별 .env + .env.example, 서버는 Secrets.</Callout>
