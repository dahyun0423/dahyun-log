## 🎬 매일 — 네 칸

```text
① 이슈     New issue → 템플릿 → 마일스톤(주차) · 담당자     → #12
② 브랜치   git switch develop && git pull
           git switch -c "feature/#12-meal-start"
③ PR       base: develop ← compare: feature/#12-…
           제목 ✨ [FEAT/#12] …   본문 closed #12
④ 머지     상대 Approve + CI 초록 → Squash and merge
           git switch develop && git pull
```

<Callout type="핵심">코드보다 **이슈가 먼저**. 이슈 없이 시작한 작업은 PR에 연결할 번호가 없다.</Callout>

## 🗺 가끔 — 새 저장소를 만들 때 10가지

| # | 할 일 | 어디서 |
|---|---|---|
| 1 | Owner가 **Org**인지 확인, Public, README·.gitignore 체크 | New repository |
| 2 | 🎉 Start 초기 커밋 push | 터미널 |
| 3 | `develop` 만들고 **기본 브랜치**로 | Settings → General |
| 4 | merge commit 끄기, Squash·Rebase 켜기, **브랜치 자동 삭제** | Settings → General → Pull Requests |
| 5 | Rulesets: main·develop — PR 필수, 승인 1, force push 금지 | Settings → Rules |
| 6 | 라벨 8개 | Issues → Labels |
| 7 | 마일스톤 (주차) | Issues → Milestones |
| 8 | Projects 보드 연결 + Auto-add | Projects 탭 |
| 9 | `.env.example` 커밋, 진짜 값은 Secrets | Settings → Secrets |
| 10 | CI 한 번 돌린 뒤 Rulesets에 **status check** 추가 | Settings → Rules |
