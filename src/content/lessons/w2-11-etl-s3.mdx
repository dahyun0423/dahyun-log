## 🎬 장면

"음식 사진 인식하려면 음식 데이터를 학습시켜야지!"라고 생각했다. 아니었다.
사진 인식은 **이미 만들어진 AI(Vision 모델)**가 하고, 우리는 그 결과를 **식약처 음식 DB에서 찾아 맞추는** 일을 한다. 그 DB를 채우는 게 ETL이다.

## 🗺 학습 vs 우리가 하는 일

| | 모델 학습(훈련) | **당당이 하는 일** |
|---|---|---|
| 무엇 | 사진 수만 장으로 AI를 새로 가르침 | 공공데이터를 **정리해서 DB에 넣고**, 이름을 **임베딩**으로 바꿔 둠 |
| 비용·시간 | GPU, 몇 주 | 스크립트 몇 개, 몇 분 |
| 정확도 확인 | 학습 곡선 | **평가셋**: 음식 사진 50장으로 Top-1·Top-5 |

## 🗺 모을 공공데이터

| 구분 | 데이터 | 번호·형태 | 언제 |
|---|---|---|---|
| **필수** | 식품영양성분DB정보 (식약처) | data.go.kr **15127578** · OpenAPI | 초기 + 주 1회 |
| **필수** | 전국통합식품영양성분정보(음식) | data.go.kr **15100070** · 파일 | 초기 1회 |
| 선택 | 병원정보서비스 (심평원) | data.go.kr 15001698 · OpenAPI | 산후 검사 기관 찾기를 할 때 |
| 보강 | Kakao Local | API | 병원 좌표·지도(선택) |

키 받는 법은 [공공데이터 API 키](/learn/w1-08-public-data). 새 데이터를 더하려면 포털에서 번호·라이선스를 확인하고 캡처한 뒤에.

## 🗺 더미 데이터의 자리

| 데이터 | 진짜 / 더미 | 어디 |
|---|---|---|
| 음식 영양 정보 | **진짜** (공공데이터) | 로컬·개발·운영 모두 |
| 가짜 사용자·식사·혈당 기록 | **더미** | 로컬·개발 서버만 — 화면 확인, QA, 부하 테스트 |
| 평가용 음식 사진 50장 | 진짜 사진(직접 찍거나 라이선스 확인) | `evals/` (운영 DB에 안 넣음) |

## 🗺 S3에 두는 것

| 무엇 | 어떻게 |
|---|---|
| 식사 사진 (AI 동의한 사용자만) | **비공개** 버킷. 서버가 presigned URL을 만들어 폰이 직접 올림. 보관 기간 정책대로 삭제 |
| DB 백업 | 서버 cron으로 매일 `pg_dump` → S3. 복구 리허설 1번 |
| 권한 | EC2에 붙인 **IAM 역할**(그 버킷만) → 서버에 키를 두지 않는다. 로컬 개발만 개인 IAM 키. 리전 ap-northeast-2(서울) |

<Callout type="요약">학습 아님 → ETL(받기·정리·넣기·임베딩). 필수 데이터는 15127578(OpenAPI)·15100070(파일). 검색은 pgvector + pg_trgm, 저장은 사용자가 고른 것만. 더미는 로컬·개발만. S3는 비공개(사진·백업).</Callout>
