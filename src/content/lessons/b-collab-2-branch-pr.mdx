## 🎬 장면

브랜치 = **진료 기록의 가지**. 본 차트(main)를 바로 고치지 않고 사본(feature)에서 작업한 뒤, 검토(PR)를 거쳐 합친다.

## 🗺 브랜치 세 종류 (내 규칙)

| 브랜치 | 역할 | 직접 작업? |
|---|---|---|
| `main` | 실제 배포되는 본 차트 | ✗ |
| `develop` | 기능들이 모이는 통합 차트 | ✗ |
| `feature/*` `fix/*` | 오늘 하는 일 하나 | ✓ |

흐름: `feature/…` →(PR, Squash)→ `develop` →(PR)→ `main` → Vercel 자동 배포

## 🗺 PR 화면에서 제일 먼저 볼 것

```text
base: develop  ←  compare: feature/notes-folders
 받는 쪽            보내는 쪽
```

- GitHub는 base를 **기본 브랜치(main)**로 자동 선택한다 → 매번 확인
- 초록 **Able to merge**면 충돌 없음, 빨간 **Can't automatically merge**면 멈추고 base부터 본다

## 🛠 배너가 없을 때

"Compare & pull request" 노란 배너는 **방금 push한 브랜치**에만 뜬다. 없으면 주소로:

```text
github.com/dahyun0423/dahyun-log/compare/받는쪽...보내는쪽
예) .../compare/develop...feature/notes-folders
```
