## 🛠 1. 로컬: DB와 Redis만 띄우기 (Spring은 IntelliJ에서)

`dangdang-be/docker/docker-compose.local.yml`

```yaml
services:
  db:
    image: pgvector/pgvector:pg16
    environment:
      POSTGRES_DB: dangdang
      POSTGRES_USER: dangdang
      POSTGRES_PASSWORD: dangdang      # 로컬 전용 값
    ports: ["127.0.0.1:5432:5432"]
    volumes: [pgdata:/var/lib/postgresql/data]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U dangdang -d dangdang"]
      interval: 5s
      retries: 10
  redis:
    image: redis:7
    ports: ["127.0.0.1:6379:6379"]
volumes:
  pgdata:
```

```bash
docker compose -f docker/docker-compose.local.yml up -d
docker compose -f docker/docker-compose.local.yml ps      # db가 healthy인지
```

`application.yaml` (로컬)

```yaml
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/dangdang
    username: dangdang
    password: dangdang
  data:
    redis:
      host: localhost
      port: 6379
```

이제 `./gradlew bootRun` → [Spring 프로젝트 해부](/learn/w2-02-spring-project)의 DataSource 에러가 사라진다.

## 🛠 2. Spring 이미지 만들기 — `docker/Dockerfile`

```dockerfile
# 1단계: 빌드 (JDK)
FROM eclipse-temurin:21-jdk AS build
WORKDIR /app
COPY gradlew settings.gradle build.gradle ./
COPY gradle gradle
RUN ./gradlew dependencies --no-daemon > /dev/null 2>&1 || true   # 의존성 캐시
COPY src src
RUN ./gradlew bootJar -x test --no-daemon

# 2단계: 실행 (JRE만)
FROM eclipse-temurin:21-jre
WORKDIR /app
ENV TZ=Asia/Seoul
RUN useradd -r -u 1001 app
COPY --from=build /app/build/libs/*.jar app.jar
USER app
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

```bash
docker build -f docker/Dockerfile -t dangdang-be:local .
```

| 줄 | 왜 |
|---|---|
| `AS build` → `COPY --from=build` | 실행 이미지에는 JDK·소스가 없다 → 가볍고 안전 |
| 의존성 먼저 복사 | 소스만 바뀌면 의존성 다운로드를 다시 안 한다(캐시) |
| `TZ=Asia/Seoul` | 알림 시각 계산(R7) |
| `useradd` + `USER app` | root로 실행하지 않는다 |

## 🛠 3. 서버용 compose — `docker/docker-compose.yml`

```yaml
services:
  app:
    image: ${DOCKER_REPO}:latest
    env_file: .env
    ports: ["127.0.0.1:8080:8080"]
    depends_on:
      db: { condition: service_healthy }
      redis: { condition: service_started }
    restart: unless-stopped
  ai:
    image: ${DOCKER_AI_REPO}:latest
    env_file: .env
    restart: unless-stopped        # ports 없음 = 안에서만
  db:
    image: pgvector/pgvector:pg16
    environment:
      POSTGRES_DB: ${DB_NAME}
      POSTGRES_USER: ${DB_USER}
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes: [pgdata:/var/lib/postgresql/data]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${DB_USER} -d ${DB_NAME}"]
      interval: 5s
      retries: 10
    restart: unless-stopped
  redis:
    image: redis:7
    command: ["redis-server", "--requirepass", "${REDIS_PASSWORD}"]
    restart: unless-stopped
  dozzle:
    image: amir20/dozzle:latest
    volumes: ["/var/run/docker.sock:/var/run/docker.sock:ro"]
    ports: ["127.0.0.1:9999:8080"]
volumes:
  pgdata:
```

- 컨테이너끼리는 **서비스 이름**으로 부른다: Spring의 DB 주소는 `jdbc:postgresql://db:5432/...`, Redis는 `redis`, AI는 `http://ai:8000`
- Dozzle은 내 맥에서 `ssh -L 9999:127.0.0.1:9999 서버` 후 `localhost:9999`로 본다

## 🛠 4. `.env` — 비밀값은 한 파일로

```dotenv
# docker/.env.example (값은 비우고 커밋)
DOCKER_REPO=
DOCKER_AI_REPO=
DB_NAME=
DB_USER=
DB_PASSWORD=
REDIS_PASSWORD=
SPRING_PROFILES_ACTIVE=prod
JWT_SECRET=
KAKAO_CLIENT_ID=
KAKAO_CLIENT_SECRET=
AWS_S3_BUCKET=
AWS_REGION=ap-northeast-2   # 키는 없음: EC2 IAM 역할로 접근
OPENAI_API_KEY=
INTERNAL_TOKEN=
```

진짜 `.env`는 커밋하지 않는다. 서버에는 CI/CD가 GitHub Secrets에서 꺼내 써 준다 → [CI/CD](/learn/w2-10-cicd)

<Callout type="요약">Dockerfile = 이미지 레시피(멀티스테이지·비root·KST). compose = 컨테이너 배치도(db 볼륨·healthcheck, 포트는 127.0.0.1). 로컬은 db·redis만, 서버는 app·ai·db·redis·dozzle. 비밀값은 .env.</Callout>
