## 🎬 장면

리뷰 = **다른 의사의 두 번째 소견**. 틀린 걸 잡는 시간이 아니라, 둘이 같이 더 안전한 처방을 만드는 시간이다.

## 🗺 리뷰받기 좋은 PR

- **작게**: 기능 하나. 파일 수십 개면 쪼갠다
- **설명**: 무엇을 / 왜 / 어떻게 확인했는지 (내 PR 템플릿의 세 칸)
- **화면이 바뀌면 스크린샷**, API가 바뀌면 요청·응답 캡처

## 🗺 코멘트 세 종류 — 앞에 붙여서 쓰기

| 머리말 | 뜻 | 예 |
|---|---|---|
| **[질문]** | 몰라서 묻기 | [질문] 여기서 useEffect를 쓴 이유가 궁금해요! |
| **[제안]** | 반영 안 해도 됨 | [제안] 이 버튼은 디자인 토큰 bg-primary를 쓰면 다크모드도 같이 될 것 같아요 |
| **[필수]** | 고쳐야 merge | [필수] 비밀번호가 코드에 그대로 있어요. 환경 변수로 옮겨야 해요 |

<Callout type="핵심">[질문]도 훌륭한 리뷰다. 설명하다가 작성자가 스스로 버그를 찾는 일이 많다.</Callout>

## 🛠 React를 다 몰라도 내가 볼 수 있는 것

1. **디자인 시스템**: 색·간격·라운드가 토큰을 쓰나? (내가 만든 디자인)
2. **상태 화면**: 로딩·빈 화면·에러 화면이 있나? (내 QA 담당)
3. **문구**: 의료 판단처럼 읽히는 말은 없나? (당당 원칙: AI가 진단하지 않는다)
4. **비밀값**: 키·비밀번호가 코드에 없나?
5. **직접 실행**: PR 브랜치를 받아서 화면을 눌러 본다 → 본 대로 적는다
