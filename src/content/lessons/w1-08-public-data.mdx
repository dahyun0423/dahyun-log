## 🛠 2. 키 찾기 — 두 개가 나온다

**마이페이지 → 데이터활용 → Open API → 활용신청 현황** → 신청한 API 클릭

```text
일반 인증키 (Encoding)  abc%2Bdef%2F...%3D%3D   ← 특수문자가 %xx로 바뀐 모양
일반 인증키 (Decoding)  abc+def/...==            ← 원래 모양
```

## 🛠 3. 첫 호출로 확인

1. 데이터 페이지의 **요청주소**와 **요청변수**(서비스키 변수 이름 포함)를 확인한다. 데이터마다 다르니 꼭 페이지에서 복사
2. 페이지의 **미리보기 / 확인** 버튼으로 먼저 한 번 본다
3. 터미널에서:

```bash
# 키는 화면에 찍히지 않게 변수로
read -s DATA_KEY          # Encoding 키 붙여넣고 Enter (화면에 안 보임)
curl "요청주소?serviceKey=$DATA_KEY&pageNo=1&numOfRows=3&type=json"
```

- JSON이 오면 성공. 승인 직후에 키 오류가 나면 **1~2시간 뒤 다시** 해 본다(키 동기화)
- 여전히 오류면 → Encoding/Decoding을 바꿔 넣지 않았는지 확인

## 🛠 4. 숨기기 — 세 군데

| 어디 | 무엇 | 커밋? |
|---|---|---|
| `.env` | 진짜 키 값 (내 컴퓨터) | ✗ `.gitignore` |
| `.env.example` | 변수 이름 + 설명, **값은 비움** | ✓ |
| GitHub **Settings → Secrets and variables → Actions** | CI·배포에서 쓸 값 | 웹에만 |

```dotenv
# dangdang-ai/.env.example
DATA_GO_KR_SERVICE_KEY=      # 공공데이터포털 서비스키 (Decoding)
DATABASE_URL=postgresql://dangdang:dangdang@localhost:5432/dangdang
```

- 골드상 팀처럼 배포용은 **Settings → Environments → production → Add secret**에 `ENV_PROD` 하나로 `.env` 전체를 넣어 두면, 배포 때 서버에 그대로 쓸 수 있다
- 키를 실수로 커밋했으면 커밋을 지워도 늦다(이미 공개됨) → **포털에서 키 재발급**이 먼저 → [비밀번호는 채팅에 쓰지 않는다](/learn/b-habits-2-secrets)
