## 🗺 개념 1. 왜 CI와 CD를 나누나

| | CI (지속적 통합) | CD (지속적 배포·전달) |
|---|---|---|
| 질문 | 이 코드를 **합쳐도** 되나? | 이걸 **사용자에게 내보내도** 되나? |
| 언제 | PR이 열릴 때마다 | develop/main에 합쳐진 뒤 (우리는 지금 버튼으로, 나중엔 main push로) |
| 하는 일 | 빌드 + 테스트 (DB가 필요해서 Postgres를 잠깐 띄움) | 이미지 굽기 → 창고 → 서버 교체 → 건강 확인 |
| 막는 것 | 깨진 코드가 팀 코드에 섞이는 것 | 검사 안 된 것·안 뜨는 것이 운영에 나가는 것 |

- **지속적 전달(Delivery)** 은 배포 직전에 사람이 승인 버튼을 누르고, **지속적 배포(Deployment)** 는 사람 없이 자동으로 나간다. 지금 우리는 'Run workflow'를 사람이 누르니 **전달**에 가깝다.
- 단계를 나누면 **어디서 깨졌는지** 바로 좁혀진다. CI가 빨간불이면 코드 문제, CD가 빨간불이면 포장·창고·서버 문제다.

## 🗺 개념 2. 이미지 · 컨테이너 · 레지스트리 · 태그

| 용어 | 빵집 | 진짜 뜻 |
|---|---|---|
| **이미지** | 진공 포장 빵 | 실행에 필요한 파일·라이브러리·설정을 묶은 **읽기 전용 꾸러미**(여러 레이어). 한 번 만들면 안 바뀐다 |
| **컨테이너** | 진열대에 올린 빵 | 이미지를 **실제로 실행한 것**. 지우고 다시 띄울 수 있고, 같은 이미지로 여러 개 가능 |
| **레지스트리** | 물류창고 | 이미지를 보관·배포하는 곳. Docker Hub가 대표. 공개/비공개 |
| **태그** | 이름표·제조번호 | `latest`(움직이는 이름표)와 `커밋 sha`(고정 번호). 롤백은 고정 번호로 한다 |

'내 컴퓨터에선 되는데?'가 사라지는 이유: 서버는 코드를 다시 빌드하지 않고 **검사를 통과한 바로 그 포장본**을 받아 실행한다.

## 🗺 개념 3. 리버스 프록시 (Nginx) — 있을 때와 없을 때

| | Nginx 없이 앱 포트를 바로 열면 | Nginx를 앞에 두면 |
|---|---|---|
| HTTPS | 앱마다 인증서를 따로 다뤄야 함 | Nginx 한 곳에서 처리(TLS 종단), Let's Encrypt 자동 갱신 |
| 주소 | 화면과 API가 다른 포트로 흩어짐 | 한 도메인 아래 `/`는 화면, `/api`는 Spring으로 나눔 |
| 보안 | 앱 포트·구조가 그대로 드러남 | 앱은 127.0.0.1에만 열고 바깥엔 80·443만 |
| 무중단 배포(나중) | 어렵다 | 새 앱으로 갈아끼울 때 Nginx가 방향만 바꾼다 |

- **포워드 프록시**는 '사용자 편'에서 밖으로 나가는 대리인(회사 인터넷 출구), **리버스 프록시**는 '서버 편'에서 들어오는 손님을 맞는 대리인이다. 손님은 리버스 프록시가 있는 줄도 모른다.
- **502 Bad Gateway** = 계산대(Nginx)는 열려 있는데 **뒤의 주방(앱)이 응답하지 않음**. 앞단 문제가 아니라 뒷단을 봐야 한다는 신호다.

## 🗺 개념 4. 비밀은 어디에 두나

| 비밀 | 금고 이름 | 누가 쓰나 |
|---|---|---|
| Docker Hub 아이디·토큰·이미지 이름 | `DOCKER_USERNAME` `DOCKER_PASSWORD` `DOCKER_REPO` | 러너(올리기), 서버(받기) |
| 서버 주소·계정·배포용 키 | `SERVER_HOST` `SERVER_USER` `SERVER_SSH_KEY` | 러너 → 서버 접속 |
| 서버 비밀값 묶음(.env) | `ENV_PROD` | 서버의 컨테이너들 |

- 원칙: **코드와 비밀을 분리**한다. 코드는 누가 봐도 되고, 비밀은 금고에서 **필요한 순간에만** 꺼낸다. 값이 새면 코드 수정 없이 그 값만 교체한다.
- 그래서 레포에는 값이 빈 `.env.example`만, 진짜 `.env`는 서버에만(권한 600) 있다.

## 🛠 첫 배포가 ✅인데 502였던 날

| 단계 | 무슨 일이 있었나 |
|---|---|
| 증상 | Actions CD는 초록 ✅, 사이트 `/actuator/health`는 502, 서버 `docker compose ps`는 텅 빔 |
| 원인 1 | 창고가 **비공개**인데 서버가 창고에 **로그인(docker login) 안 함** → `pull access denied` |
| 원인 2 | 서버 스크립트에 `set -e`가 없어서 **중간에 실패해도 끝까지 가서 ✅** |
| 고침 (PR #2) | 서버에서 `docker login` → `set -e` → `.env` 권한 600 → **health가 UP일 때만 성공** |
| 교훈 | '초록불'은 **스크립트가 끝났다**는 뜻이지 **서비스가 떴다**는 뜻이 아니다. 마지막에 진짜 서비스를 확인하는 단계를 넣는다 |

## 🛠 버튼 누르고 2분 — 타임라인

| 시간 | 단계 | 누가 |
|---|---|---|
| 0:00 | Run workflow (develop) | 다현 |
| ~0:10 | 러너 준비, 코드 받기 | GitHub |
| ~0:10–1:20 | 이미지 굽기 → Docker Hub 올리기 | 러너 |
| ~1:20–1:30 | compose 파일을 서버로 | 러너 → EC2 |
| ~1:30–2:00 | .env · 로그인 · pull · up · health 확인 | EC2 |
| 2:00 | ✅ 그리고 https에서 UP | 사용자 |

<Callout type="핵심">자동 배포 = **검수(CI) → 포장(이미지) → 창고(레지스트리) → 매장 교체(서버 pull·up) → 계산대(Nginx·HTTPS)**. 비밀은 금고(Secrets)에, 성공 기준은 '스크립트 종료'가 아니라 '서비스 UP'.</Callout>
