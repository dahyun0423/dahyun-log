## 🎬 장면

이슈를 만들 때마다 "제목 형식이 `[Feat]: `였나 `[FEAT]`였나…", PR마다 "체크리스트 뭐 있었지…".
골드상 팀은 이걸 **사람이 기억하지 않게** 했다. New issue를 누르면 칸이 이미 채워져 있다.

## 🗺 파일은 어디에

```text
dangdang-gdm/.github            ← Org 공통 (자기 템플릿 없는 저장소 전부에 적용)
├── profile/README.md           ← Org 첫 화면
├── ISSUE_TEMPLATE/
│   ├── ✨-feature.md
│   ├── 🐛-bug.md
│   ├── ♻️-refactor.md
│   ├── 🚀-deploy.md
│   └── 📝-docs.md
└── PULL_REQUEST_TEMPLATE.md
```

템플릿 내용은 옵시디언 `13_당당 초기 세팅 가이드` 3절에 다 있다. 복사해서 쓴다.

## 🗺 템플릿 머리말 읽기

```markdown
---
name: "✨ Feature"          ← New issue 화면에 보이는 템플릿 이름
about: 새로운 기능을 구현합니다  ← 이름 아래 설명
title: "[Feat]: "           ← 제목 칸에 미리 들어갈 글자
labels: feat                ← 자동으로 붙는 라벨 (라벨이 먼저 만들어져 있어야 함)
assignees: ''               ← 담당자 (비워 두고 직접 고름)
---
## 📝 구현 기능 설명         ← 여기부터는 본문 칸에 미리 채워짐
```

- `---` 사이를 **머리말(front matter)**이라고 한다. 이 사이가 틀리면(따옴표, 콜론 뒤 공백) 템플릿 목록에 안 뜬다
- 웹에서 만들고 싶으면: 저장소 **Settings → General → Features → Issues → Set up templates**

## 🛠 README — 골드상 팀 + 우리가 더할 것

| 골드상 팀 README | 당당이 더하는 것 |
|---|---|
| 한 줄 소개 · 키워드 · 기간 | 그대로 |
| 🏆 수상 내역 | 발표 후 채움 |
| 💡 해결하려는 문제 · 서비스 개요 (인용문 `>`) | 수치는 계획서 근거 그대로(유병률 12.4%, 산후 검사율 42.9%) |
| 주요 기능 체크박스 · 핵심 기술 나열 | 그대로 |
| 발표 슬라이드 이미지만 | **아키텍처 · ERD · 시연 영상 섹션을 따로** |
| Contributors 표 + 아바타 | 그대로 |
| shields.io 뱃지 (`style=for-the-badge`) | 그대로 |
| FE README는 기본 템플릿 | **저장소마다 실행 방법·폴더 구조·환경변수 표** |

## 🛠 저장소 첫 커밋 순서 (be 예시)

| 순서 | 메시지 | 담을 것 |
|---|---|---|
| 1 | `🎉 Start: 당당 백엔드 프로젝트 초기 세팅` | Spring Initializr로 만든 뼈대 |
| 2 | `➕ Dependency/Plugin: Security, JPA, Flyway, Redis, springdoc, Spotless 추가` | `build.gradle` |
| 3 | `🔧 Settings: application.yml 환경변수 분리, .env.example 추가` | 설정 파일 |
| 4 | `🔧 Settings: 로컬 docker-compose(postgres+pgvector, redis) 추가` | `docker/` |
| 5 | `🚀 Deploy: PR CI(spotlessCheck, build, test) 추가` | `.github/workflows/ci.yml` |
| 6 | `📝 Docs: README 작성` | `README.md` |

- `git add .` 말고 **경로 단위로** 담는다 → [커밋 하나 = 이야기 하나](/learn/b-collab-1-commit)
- 템플릿은 `.github` 저장소에 `📝 Docs: 이슈 템플릿, PR 템플릿 추가`로 먼저 올린다

<Callout type="요약">템플릿은 `.github` 저장소에 한 번 → 이슈 만들면 제목·라벨 자동 → 브랜치 `feature/#번호-설명` → PR 본문 `closed #번호` → develop(기본 브랜치)에 머지되면 이슈 자동 닫힘</Callout>
